The record now answers over a Unix socket, and a close labels the pull request.

`internal/api` serves `GET /v1/flows`, `/v1/flows/{flow}/jobs`, `/v1/flows/{flow}/jobs/{owner}/{repo}/{key}`, `/v1/stream` and `/v1/health` from the record. An unknown flow or job is 404. A job card carries the identity, `ref`, `title`, state, verdict, `cause`, `alert` and `link`; the detail adds tasks with `n`, `short`, `at`, actions, `pc`, `evidence` and `tools`. The stream sends `{flow,owner,repo,key}` for every job on connect, then one event per change.

`internal/github` signs the App JWT with the key, resolves the installation per repository, mints a token and adds the `blocked` label. It makes no other call. The key and a token never enter an error, a log or a response.

`dispatch.json` gains `app_id` and `key_path`; the key is read at boot. `cmd/dispatch` gains `--socket` (default `~/.dispatch/dispatch.sock`) and serves the API there. An M0 database is migrated when it opens.

A close that ends an unmerged job calls the label writer once for the pull request. A rejected write is kept on the jobs as `alert`, and the delivery is kept. A merged close writes no label.
